# Lab 3 Part A: Stateless Chatbot with Ollama

## Overview

This lab demonstrates how a basic chatbot works when it has **no memory**.

The script sends individual prompts to a local Ollama model using the Ollama API. Each message is treated as a brand-new request, meaning the model does **not** remember anything from previous interactions.

This is important because it shows one of the biggest limitations of simple chatbot implementations:

> Without conversation history, the chatbot cannot understand follow-up questions.

---

## What This Script Teaches

This script helps explain:

- How to send a prompt to Ollama from Python
- How to call a local LLM using an HTTP API
- Why conversation memory matters
- The difference between a single prompt and a real chatbot conversation
- Why follow-up questions fail without chat history

## The Script

```python
#!/usr/bin/env python3
"""
Lab 3 Part A: Stateless Chatbot

This script demonstrates the problem with a chatbot that has no memory.

Each time the user sends a message, the script sends that message to Ollama
as a brand-new prompt.

That means the model does not know what was asked before.
"""

import requests
import json


def simple_chat(user_message: str, model: str = "llama3.2:3b") -> str:
    """
    Send a single user message to Ollama.

    This function does NOT include conversation history.

    Parameters:
        user_message (str):
            The message or question from the user.

        model (str):
            The Ollama model to use.
            By default, this uses llama3.2:3b.

    Returns:
        str:
            The response generated by the model.
    """

    # Ollama's local API endpoint for text generation
    url = "http://localhost:11434/api/generate"

    # The request payload sent to Ollama
    payload = {
        "model": model,

        # This is the user's message.
        # Notice that we only send the current message.
        # No previous messages are included.
        "prompt": user_message,

        # stream=False tells Ollama to return the full response at once
        "stream": False,

        # Model behavior settings
        "options": {
            # Higher temperature means more creative/random responses.
            # Lower temperature means more predictable responses.
            "temperature": 0.7
        }
    }

    try:
        # Send the request to Ollama
        response = requests.post(url, json=payload, timeout=30)

        # Raise an error if the HTTP request failed
        response.raise_for_status()

        # Convert the JSON response into a Python dictionary
        data = response.json()

        # Return only the generated response text
        return data.get("response", "")

    except requests.exceptions.ConnectionError:
        # This happens if Ollama is not running
        return "Error: Cannot connect to Ollama. Is it running? Try: ollama serve"

    except Exception as e:
        # Catch any other error and return it as a readable message
        return f"Error: {e}"


if __name__ == "__main__":
    print("🤖 Stateless Chatbot Demo (Ollama)")
    print("=" * 70)

    # First question
    # The model can answer this because the full question is provided.
    print("\n👤 User: What is OSPF?")
    response1 = simple_chat("What is OSPF?")
    print(f"🤖 Bot: {response1}\n")

    # Second question
    # This question depends on memory.
    # But the model only receives this one sentence.
    # It does not receive the previous question.
    print("👤 User: What did I just ask you?")
    response2 = simple_chat("What did I just ask you?")
    print(f"🤖 Bot: {response2}\n")

    # This explains the failure
    print("❌ FAILURE: The bot doesn't remember!")
    print("   Each API call is independent.")

    # This points learners to the next version of the lab
    print("\n💡 Next: See chatbot_v2_with_memory.py for the solution!")
```

---

## How It Works

The important part of this script is the `simple_chat()` function.

Every time this function runs, it sends only one message to the model:

```python
"prompt": user_message
```

That means this:

```python
simple_chat("What is OSPF?")
```

and this:

```python
simple_chat("What did I just ask you?")
```

are two completely separate API calls.

The model does not automatically know that the second question came after the first one.

---

## Why the Bot Fails

The chatbot fails because it is **stateless**.

A stateless chatbot does not keep track of:

* Previous user messages
* Previous assistant responses
* Conversation context
* Follow-up questions
* Topic history

So when the user asks:

```text
What did I just ask you?
```

The model only sees that single question.

It does not see:

```text
What is OSPF?
```

Because that earlier question was never included in the second API request.

---

## Key Lesson

Large Language Models do not automatically remember previous API calls.

To build a real chatbot, you need to send the conversation history with each new request.

For example, instead of sending only this:

```text
What did I just ask you?
```

You need to send something more like this:

```text
User: What is OSPF?
Assistant: OSPF stands for Open Shortest Path First...
User: What did I just ask you?
```

That extra context gives the model enough information to answer correctly.

---

## Why This Matters for Network Automation

This matters because many automation workflows need context.

For example, in a network operations chatbot, a user may ask:

```text
What routers are down?
```

Then follow up with:

```text
Which ones are in the Atlanta site?
```

Then ask:

```text
Can you open a ticket for those?
```

Without memory, the chatbot would not know what “those” refers to.

That is why conversation history is required when building useful AI assistants for NetOps, SecOps, and IT operations.
